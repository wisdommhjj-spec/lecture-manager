# 기획안과의 차이

기획안: 「강의행정서류패키지」 (2026-10-24 제출)

| # | 기획안 | 구현 | 이유 |
|---|---|---|---|
| 1 | 서비스 이름 「강의행정서류패키지」 | **「출강매니저」** | 서류 패키지에 일정·강사·기관 관리까지 합쳐져서, 출강 사무 전체를 다루는 이름으로 바꿈 |
| 2 | 서류만 만드는 도구 | **출강 일정 관리와 합침** (목록·달력, 강사, 기관) | 서류에 들어가는 정보(기관, 날짜, 강사, 단가)가 모두 일정에 있음. 일정을 한 번 등록하면 서류를 바로 만들 수 있어 반복 입력이 줄어듦. 이전에 만들어 둔 출강 일정 관리 화면의 기능을 참고함 |
| 3 | 서류 생성 → 바로 zip | **최종 확인 화면 추가**: 미리보기, 빠진 항목 경고, 강의계획서 바로 수정, 확인 체크 후에만 수락 | 개인정보와 금액이 들어가는 서류라서, 사람이 확인하지 않고 묶어 보내면 위험함. 실제 업무 담당자(본인) 요청 |
| 4 | 메일 자동 발송은 "하지 않을 것" | **수락하면 zip 생성 + 기관 담당자에게 메일 발송** | 확인 화면이 생겨서 "사람이 수락한 것만 보낸다"가 보장됨. 서류를 모은 뒤 메일에 첨부하는 일까지 줄여야 시간 절감 효과가 큼. 대신 "수락 없이 자동으로 보내기"를 하지 않을 것으로 옮김 |
| 5 | 강의계획서 양식 미정 | **바움 실제 양식(2026학년도)에 맞춤**, 과목별 내용 묶음을 보관함에 저장 | 실제 샘플을 받아 그 구조(기본 정보 표, 교육 목적, 차시별 표, 기대효과)를 그대로 옮김 |
| 6 | 강사카드 1종 | 강사카드를 **배정된 강사 수만큼** 한 파일에 (한 사람당 한 쪽) | 한 출강에 강사가 여러 명 투입됨 (데모 기준 2~5명) |
| 7 | (없음) | **테스트 모드, 발송 암호** | 공개 데모 주소에서 아무나 실제 학교로 메일을 보내지 못하게 함 |
| 8 | (없음) | 데이터를 **브라우저에 저장**, 백업 파일로 옮기기 | 제출 기한(10/30) 안에 동작하는 MVP를 먼저 만들기 위해. 여러 사람이 함께 쓰는 서버 저장(Supabase)과 로그인은 실사용 단계로 미룸 |

## 기획안 그대로인 것

- 서류 5종: 강사카드, 견적서, 사업자등록증, 계좌사본, 강의계획서
- 계좌사본: 기본은 법인계좌, 기관이 요청하면 해당 강사의 개인계좌
- 묶음 이름 규칙: `yyyy.mm_기관명.zip` (월은 출강일 기준)
- 사람이 판단할 일: 견적 단가, 법인/개인 계좌 선택, 강의계획서 최종 문구, 보낼지 말지 결정
- 기관 고유 양식(hwp) 자동 맞춤, 세금계산서 발행은 하지 않음
