### 막힌 곳과 복구한 방법

| 막힌 곳 | 복구 |
|---|---|
| 바움 홈페이지가 그누보드5(PHP 7.3)이고 https가 없어, 웹앱을 페이지 안에 넣으면 구글 로그인과 파일 내려받기가 막힘 | 홈페이지는 건드리지 않고 **하위 주소(`manager.baumsc.com`)를 따로 연결**하고 메뉴에 링크만 거는 방식으로 결정 |
| 공개 데모 주소에서 누구나 "보내기"를 누르면 실제 학교에 메일이 갈 수 있음 | 서버에 **테스트 모드**(정해 둔 주소로만 발송)와 **발송 암호**를 추가 |
| 기본 `.gitignore`의 `.env*` 규칙 때문에 제출에 필요한 `.env.example`까지 저장소에서 빠짐 | `!.env.example` 예외를 추가하고, 실제 데이터가 담길 수 있는 `*.zip`, 백업 json, `/private` 폴더는 제외 목록에 추가 |
| 이 컴퓨터에 워드/한글이 없어 생성한 .docx를 직접 열어 볼 수 없음 | 화면 미리보기를 워드 파일과 같은 데이터로 그리게 하고, 생성된 .docx 6개의 문서 구조(XML)가 정상인지 스크립트로 검사. 실제 워드·한글에서 열어 보는 것은 내가 확인 (아래) |
| 첫 Vercel 배포가 "Vulnerable version of Next.js detected"로 막힘 | Next.js를 15.5.4 → 15.5.28(보안 패치)로 올림. 같이 `npm audit`로 점검해 메일 라이브러리 nodemailer도 7.0.6 → 10.2.1로 올림. 다시 빌드·린트 통과 후 재배포 |
| `lecture-manager.vercel.app` 주소는 이미 다른 사람이 쓰고 있었음 | Vercel이 준 `lecture-manager-two.vercel.app`을 데모 주소로 사용 |
| 메일 테스트 주소가 `ㅡㅗ***@ㅜㅁㅍㄷㄱ.채ㅡ`처럼 들어감 (Vercel 환경 변수를 **한글 자판 상태**로 입력) | 서버의 설정 상태 응답(가린 주소)으로 발견 → 영문 상태로 다시 입력 |
| 발송 암호가 계속 "맞지 않습니다" | 암호 입력칸은 브라우저가 영문만 받는데, 저장된 암호가 한글로 입력되어 있었음 → 영문으로 다시 저장. 서버는 앞뒤 공백을 무시하도록 고침 |
| 암호 통과 후 "메일을 보내지 못했습니다" | 화면 문구만으로 원인을 알 수 없어 **오류 코드를 함께 보여 주도록** 고침. 에이전트가 직접 값을 내려받아 점검하려 했으나 Vercel의 Sensitive 변수는 내려받을 수 없음 → 값은 내보내지 않고 모양(글자 수·공백·한글)과 Gmail 로그인 결과만 알려 주는 **"메일 설정 점검" 버튼**을 설정 화면에 추가. 앱 비밀번호의 띄어쓰기(구글이 4자리씩 띄어 보여 줌)를 서버가 자동으로 빼도록 고친 뒤 로그인 성공 |
| 제출 기한이 이틀이라 로그인·서버 DB까지 하기 어려움 | 데이터를 브라우저에 저장하고 백업 파일로 옮기는 방식으로 먼저 완성. 서버 DB와 로그인은 실사용 단계로 미룸 ([기획안과의 차이](기획안과의-차이.md) 8번) |
